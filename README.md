# Agent Flow

面向编码 Agent 的文档驱动工作流。理解、规划、执行、核验四个入口可以独立使用；不需要 Python、状态数据库、全局阶段调度或特定 Agent 平台。

默认在当前目录由单 Agent 工作。用户可选择 worktree、多个 Agent 或两者组合，主流程仍由 Markdown 说明，不由脚本推进。

## 开始使用

保留本仓完整目录，向 Agent 明确**工作流资源根**和**实际目标项目**。例如：

```text
先读取 /path/to/agent-flow/AGENTS.md。
目标项目是 /path/to/my-project，遵守其中适用规范。
修复已有测试指出的问题，只改必要内容，运行目标检查，不提交。
```

已有项目规范、任务记录和测试优先复用，不要求先登记仓库、初始化 `.workspace` 或生成文档。没有 Git 的目录也可以使用普通路径。

有原生 Skill 发现能力的宿主可按其机制发现 `.agents/skills/`。发现规则因宿主而异，不承诺放到目录就自动生效。没有发现能力时直接读所需 `SKILL.md`，它就是操作说明。

Skill 的相对链接依赖本仓 `docs/`、`templates/` 布局。**不要只复制一个 SKILL.md 就假定其依赖可用**；优先从完整 checkout 使用，确需复制/安装时一并处理引用和依赖，不覆盖项目现有入口或全局 Skill。

## 选择工作方式

| 当前请求 | 入口 | 结果 |
| --- | --- | --- |
| 调查原因、解释架构或重要未知 | [flow-explore](.agents/skills/flow-explore/SKILL.md) | 有来源的事实、推断和未知；可在此结束 |
| 目标明确，需要方案、取舍或任务依赖 | [flow-plan](.agents/skills/flow-plan/SKILL.md) | 最小充分方案、必要计划与执行安排 |
| 实施、修复、继续已有方案 | [flow-execute](.agents/skills/flow-execute/SKILL.md) | 实际改动、局部检查和进展 |
| 核验已有结果或实施收尾 | [flow-verify](.agents/skills/flow-verify/SKILL.md) | 当前可证实结果、缺口和限制 |

明确小改通常直接 execute → verify；已有方案不重新规划；只读问题不进入实施。箭头不是强制工具调用、会话切换或审批阶段。授权范围内可连续推进，遇到真实范围、决策或权限阻塞才暂停。

## 隔离与协作

工作位置和执行者是两个独立选择：

| 位置 | 执行者 | 要点 |
| --- | --- | --- |
| 当前 checkout | 单 Agent | 默认，无须给每个小改出模式选择题 |
| worktree | 单 Agent | 隔离当前工作树，不隔离数据库等共享资源 |
| 当前 checkout | 多 Agent | 分析/审查或轮流实施；同时仅一个写入者 |
| worktree | 多 Agent | 独立任务可在条件允许时并行，先明确整合和最终验收目标 |

可以这样选择：

```text
按现有方案执行，使用 worktree + 多 Agent。
先明确基线、路径、分工、允许写入范围及如何汇总成果。
不提交、推送、合回或清理；没有授权覆盖的操作先说明。
```

模式选择不隐含其他 Git/外部操作权限。获准委派后使用宿主已有工具，先读可用 profiles/notes，并在任务提示中写清实际职责，不依赖 profile 名称。无 Git 或无委派能力时如实说明选择限制，不伪装或静默换模式。

详见按需读取的 [执行规范](docs/execution.md)。本仓没有 Agent 队列、worktree 管理器或宿主插件。

## 文档按需要生成

简单任务直接回复。需要持久记录时优先用项目已有位置；没有适用位置才从 [模板索引](templates/README.md) 选择。

八模板可用，不是每项任务的八个产物。普通任务通常一份工作记录；需要独立读者/审阅时再拆需求、设计、计划或验证说明。内容拆出后成为该内容唯一权威，主记录只引用。

独立目录可选择以下布局，但不是启动前提：

```text
.workspace/
  workspace.md              项目规则、事实入口和已选扩展的短索引
  items/<slug>/work.md       仅需要跨会话记录的任务
```

根 [AGENTS.md](AGENTS.md) 明确路由到当前适用的本地入口；不依赖宿主自动发现 `workspace.md`。本仓忽略 `.workspace/`，私有内容仍需自行访问控制和备份。

写作职责与更新规则见 [文档规范](docs/documents.md)，验证结果的复用和完成边界见 [验证规范](docs/verification.md)。不默认创建 JSON 状态、日期版、阶段报告或重复摘要。

## 补充自己的流程

用项目规则补充约束，用标准 Skill 提供专业能力，用可读调用条件组合它们。不需要修改核心或注册 Provider/Action。

```text
本次只有涉及客户端交接时才读取我们已有的接口指南 Skill。
若用户明确要求 PR，再使用选定的 PR 工具；本地实现验收不要求发布。
扩展返回实际目标、来源、结果、证据位置和限制，不用 success 替代验收。
```

专业模板随扩展提供，未选能力不加载；安装/选择扩展不授权其外部写入。参见 [扩展约定](docs/extensions.md) 和可直接读取、无外部副作用的 [local-evidence 示例](docs/examples/local-evidence/SKILL.md)。该示例不在核心 inventory，不默认运行。

## 接入与维护

- 先明确目标和适用规则，保留现有 AGENTS/任务记录，不用本仓覆盖已有规范。跨目录访问必须由宿主权限允许；链接并不授予文件访问权。
- 更新本仓前查看来源和公共改动，先了解目标版本差异。使用自己批准的版本控制/文件替换方式；不自动 stash/reset、处理冲突或改业务仓。
- `.workspace`、扩展源码和其他私有资料单独保留；只备份必须保留的内容，不把凭据加入公共提交。被忽略不等于已备份。
- 出现缺工具、路径不唯一、旧结果失效时，核对本项实际需要的能力与来源，不运行全工作区初始化或读取无关凭据。

## 验证本项目

维护者在仓根运行以下命令，需要 Python 3.10+；普通使用者不需要 Python：

```bash
python3 -B -m unittest discover -s tests -p 'test_*.py' -v
git diff --check
```

维护检查验证文档布局、链接和 Skill 元数据，不执行用户工作流，也不证明 Agent 行为。独立前向试用的请求、观察与覆盖限制见 [验收说明](tests/README.md)。

## 范围与保证

本项目不内置接口指南、PR/发布、需求平台、语言/数据库手册、旧 kit 迁移或 IDE/Paseo 插件。使用者可按需选择自己的工具。

Markdown 是协作约定，不是安全沙箱、并发事务系统或用户批准证明。工具权限、只读账号、受保护分支、CI 和具体副作用工具负责可强制的边界；不要把流程简化解释为这些保障已经自动等价。
