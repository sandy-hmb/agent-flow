# Agent Flow

面向编码 Agent 的文档驱动工作流。调查、规划、执行、核验四个入口可独立使用，适用于日常开发、问题调查和已有成果核验。

默认在已确定目标的现有工作目录由单 Agent 工作。用户可选择 worktree、多个 Agent 或两者组合，通过 Markdown 约定目标、范围和验收。

## 初始化与接入

1. 保留本仓完整目录，确定**工作流资源根**。Skill 引用依赖本仓 `docs/`、`templates/` 布局；单独复制 `SKILL.md` 时需同时处理这些依赖。
2. 创建或复用工作区入口。默认位置为 `<工作流资源根>/.workspace/workspace.md`，可参考 [workspace 模板](templates/workspace.md)；用户或宿主已明确绑定其他入口时维护那个文件。写明业务仓路径、职责、默认目标/任务路由、规则和已选扩展，优先引用已有说明。
3. 把资源根 `AGENTS.md` 和工作区入口关联到**宿主真正读取的 AGENTS 或启动指令**。在已有规则中补充引用，不覆盖原文件；仅放置 `workspace.md` 不代表宿主会发现它。初始化只维护已获准的入口，不自动修改业务仓。
4. 开始任务时先读取入口，按 [上下文规范](docs/context.md) 定位目标，再加载对应 Skill。先读本次涉及仓的规则和概览，再按需读代码；索引中的其他仓无需加载，列入索引也不授权修改它们。

例如，完整资源位于 `/work/agent-flow`，业务仓位于 `/work/service`。以下内容可写入 `/work/agent-flow/.workspace/workspace.md`：

```markdown
# 开发工作区

工作流资源根：../
仓：service；路径：../../service；职责：业务服务。
默认目标：service。
规则入口：[service 规则](../../service/AGENTS.md)。
已选扩展：无。
```

多仓时可用同一个入口声明路由，无需为每仓创建新记录：

```markdown
# 产品工作区

工作流资源根：../

| 仓 | 路径 | 职责 | 规则入口 |
| --- | --- | --- | --- |
| service | ../../service | 业务服务 | ../../service/AGENTS.md |
| web | ../../web | 客户端 | ../../web/AGENTS.md |

任务路由：接口与服务端任务指向 service；页面任务指向 web；联调涉及两仓。
默认目标：service。
已选扩展：涉及客户端交接时读取已有接口指南，入口为 ../../service/docs/api-guide.md。
```

示例路径需替换为实际存在的路径。相对路径从**声明文件自身目录**解析，包括仓路径和规则入口。路由优先于默认目标；用户本次明确指定的目标优先，完整优先顺序和歧义处理统一见 [上下文规范](docs/context.md)。目标项目自己的 workspace 文件仅在其规则明确引用时读取，不因同名替换入口或递归寻找。

宿主启动指令示例（也可作为已有 AGENTS 中的补充说明）：

```text
使用 /work/agent-flow 作为工作流资源根，先读取其中的 AGENTS.md。
工作区入口绑定为 /work/agent-flow/.workspace/workspace.md，进入任务时读取。
保留并遵守宿主原有规则和所选目标项目的适用规范。
```

本仓 `AGENTS.md` 已声明默认入口；显式绑定其他入口时使用绑定位置。显式入口缺失或选中仓路径失效须报告，不能回退扫描。未配置且默认文件不存在时仍支持直接指定目标，不强制初始化，例如：

```text
先读取 /work/agent-flow/AGENTS.md；本次目标是 /work/service。
修复已有测试指出的问题，只改必要内容，运行目标检查，不提交。
```

已有项目规范、任务记录和测试优先复用，没有 Git 的目录也可使用普通路径。终端停在资源根不代表任务目标就是 Agent Flow；维护本项目时直接明确指定它。

有原生 Skill 发现能力的宿主可按其机制发现 `.agents/skills/`。发现规则因宿主而异，不承诺放到目录就自动生效。没有发现能力时直接读所需 `SKILL.md`，它就是操作说明。

## 选择工作方式

| 当前请求 | 入口 | 结果 |
| --- | --- | --- |
| 调查原因、解释架构或重要未知 | [flow-explore](.agents/skills/flow-explore/SKILL.md) | 有来源的事实、推断和未知；可在此结束 |
| 目标明确，需要方案、取舍或任务依赖 | [flow-plan](.agents/skills/flow-plan/SKILL.md) | 最小充分方案、必要计划与执行安排 |
| 实施、修复、继续已有方案 | [flow-execute](.agents/skills/flow-execute/SKILL.md) | 实际改动、局部检查和进展 |
| 核验已有结果或实施收尾 | [flow-verify](.agents/skills/flow-verify/SKILL.md) | 当前可证实结果、缺口和限制 |

明确小改通常直接 execute → verify；已有方案不重新规划；只读问题不进入实施。箭头不是强制工具调用、会话切换或审批阶段。授权范围内可连续推进，遇到真实范围、决策或权限阻塞才暂停。

## 隔离与协作

工作位置和执行者是两个独立选择：

| 位置 | 执行者 | 要点 |
| --- | --- | --- |
| 目标现有工作目录 | 单 Agent | 默认，无须给每个小改出模式选择题 |
| worktree | 单 Agent | 隔离当前工作树，不隔离数据库等共享资源 |
| 目标现有工作目录 | 多 Agent | 分析/审查或轮流实施；同时仅一个写入者 |
| worktree | 多 Agent | 独立任务可在条件允许时并行，先明确整合和最终验收目标 |

可以这样选择：

```text
按现有方案执行，使用 worktree + 多 Agent。
先明确基线、路径、分工、允许写入范围及如何汇总成果。
不提交、推送、合回或清理；没有授权覆盖的操作先说明。
```

选择 worktree 前先核实目标仓，模式选择不隐含其他 Git/外部操作权限。获准委派后先读宿主提供的角色配置及说明（如 Paseo 的 profiles/notes），再选择启动配置，并在任务提示中写清实际职责，不依赖配置名称。无 Git 或无委派能力时如实说明限制，不静默换模式。

详见按需读取的 [执行规范](docs/execution.md)。

## 文档按需要生成

简单任务直接回复。需要持久记录时优先用项目已有位置；没有适用位置才从 [模板索引](templates/README.md) 选择。

八模板可用，不是每项任务的八个产物。普通任务通常一份工作记录；需要独立读者/审阅时再拆需求、设计、计划或验证说明。内容拆出后成为该内容唯一权威，主记录只引用。

工作区入口与需要持久记录的任务可采用以下布局：

```text
.workspace/
  workspace.md              仓路径、职责、任务路由/默认目标、规则与扩展索引
  items/<slug>/work.md       仅需要跨会话记录的任务
```

本仓忽略 `.workspace/`，私有内容仍需自行访问控制和备份；初始化示例不会自动创建或修改本机私有入口。

写作职责与更新规则见 [文档规范](docs/documents.md)，验证结果的复用和完成边界见 [验证规范](docs/verification.md)。持续更新已有记录，其他位置引用相应的权威内容。

## 补充自己的流程

用项目规则补充约束，用标准 Skill 提供专业能力，在工作区入口或项目规则中写明调用条件。

```text
本次只有涉及客户端交接时才读取我们已有的接口指南 Skill。
若用户明确要求 PR，再使用选定的 PR 工具；本地实现验收不要求发布。
扩展返回实际目标、来源、结果、证据位置和限制，不用 success 替代验收。
```

专业模板随扩展提供，未选能力不加载；安装/选择扩展不授权其外部写入。接入方式见 [扩展约定](docs/extensions.md)；需要核对已有本地报告时，可选择 [local-evidence 示例](docs/examples/local-evidence/SKILL.md)。

## 接入与维护

- 先明确目标和适用规则，保留现有 AGENTS/任务记录，不用本仓覆盖已有规范。跨目录访问必须由宿主权限允许；链接并不授予文件访问权。
- 更新本仓前查看来源和公共改动，先了解目标版本差异。使用自己批准的版本控制/文件替换方式；不自动 stash/reset、处理冲突或改业务仓。
- `.workspace`、扩展源码和其他私有资料单独保留；只备份必须保留的内容，不把凭据加入公共提交。被忽略不等于已备份。
- 出现缺工具、路径不唯一、旧结果失效时，核对本项实际需要的能力与来源，不运行全工作区初始化或读取无关凭据。

## 验证本项目

维护者在仓根运行以下命令，需要 Python 3.10+；普通使用者不需要 Python：

```bash
python3 -B -m unittest discover -s tests -p 'test_*.py' -v
git diff --check
```

维护检查验证文档布局、链接和 Skill 元数据，不执行用户工作流，也不证明 Agent 行为。独立前向试用的请求、观察与覆盖限制见 [验收说明](tests/README.md)。

## 适用边界

接口指南、PR/发布、需求平台、语言与数据库等专业能力由使用者按需选择和接入。

Markdown 记录协作约定；实际操作仍受用户授权和宿主权限约束。工具权限、只读账号、受保护分支与 CI 承担各自可强制的边界，文档约定不替代这些保障。
