# 仓库事实

> 仅在仓事实复杂且已有说明不足时使用。最低信息：实际路径、职责、适用规则、已有检查入口及未知。项目维护者按事实变化更新；生成时删除提示与无关条件章节。

## 实际对象与职责

> 写仓名称、真实仓/项目路径、职责及本次相关边界，供工作区入口引用；相对路径从本文件目录解析。只有确有时效性时记录核对日期/版本；非 Git 项目不编造分支或 commit。列入入口不授予全仓或其他仓的写入权限。

## 适用规则与关键入口

> 引用适用规则、概览、源码/配置入口和已有说明；先读规则与概览，再按当前任务读取必要代码，不将本节变成全仓加载清单。仅在仓规则明确引用时加载仓内 workspace 入口，不复制仓内手册。

## 已有检查入口

> 记录实际已知的检查命令或核对方法、工作目录、前提和覆盖边界。入口存在不代表已执行；未知命令明确未知，不猜测默认构建工具。

## 依赖与共享资源（条件）

> 仅写本次相关的仓间依赖、环境、端口、数据或共享缓存限制；不写凭据，不将本机路径当作他人可访问入口。

## 未知与风险（条件）

> 列影响使用的缺口及核实方式；没有则删除。任务进展和验收结果仍放当前任务记录，不放本文件。
