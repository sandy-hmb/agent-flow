# 按需模板索引

仅在真正落盘对应文档时读取单个模板，不预读，也不按阶段凑齐多份文件。没有持久记录需要时直接回复；需要落盘时先按 [文档规范](../docs/documents.md) 复用项目已有文件或已选扩展模板。

## 常用核心模板

| 模板 | 启用场景 | 维护者 | 核心槽位 | 维护规则 |
| --- | --- | --- | --- | --- |
| [workspace](workspace.md) | 初始化或维护工作区入口（默认 `.workspace/workspace.md`） | 项目维护者 | 资源根、仓路径与职责、任务路由/默认目标、规则与扩展 | 仅维护定位与路由，路径从本文件目录解析 |
| [work](work.md) | 跨会话或复杂任务的单一主记录（含常规目标验收与验证结果） | 协调者 / 当前执行者 | 5～8 行当前概览、目标与验收、关键事实与方案、最新验证 | 原地覆盖过时概览与作废轮次验证，严禁写成追加流水账 |
| [investigation](investigation.md) | 需独立审阅或复用的排障、根因分析与架构调查报告 | 调查者 | 问题与结论摘要、范围与来源、事实证据链、待核实项 | 结论前置；来源或结论变化时原地更新 |
| [design](design.md) | 关键技术取舍或跨模块契约需独立审阅时 | 方案负责人 | 背景目标、现状与不变边界、方案取舍、核心契约、兼容与验证方向 | 只展开真实变化与风险，不复制需求全文 |
| [plan](plan.md) | 多任务依赖、分步交付或协作交接需独立计划时 | 协调者 / 计划维护者 | 权威依据链接、可验证交付任务、执行安排、整体验收 | 引用规格章节不重述设计；执行进度统一在 `work.md` 维护 |

## 低频独立交付模板

常规业务任务**不启用**以下模板（目标验收与最新验证直接写在 `work.md`，仓库入口直接写在 `workspace.md`）；仅在用户或项目明确要求独立成文交付时按需读取：

| 模板 | 启用门槛 | 核心槽位 |
| --- | --- | --- |
| [requirements](requirements.md) | 用户明确要求独立评审需求规格说明 | 背景与目标、范围与非目标、可观察验收、约束与待决定项 |
| [verification](verification.md) | 用户或外部流程明确要求独立交付验证报告 | 结论与验收环境、验收项与检查结果、未关闭项与后续动作 |
| [repository](repository.md) | 多仓/复杂仓库事实需单独建档且仓内现有文档不足 | 仓库定位与职责、规则与关键入口、常用检查命令、共享限制 |

## 通用使用准则

- **删净提示与空章节**：模板中的 `>` 引用块仅为槽位引导，生成文档时全部删除；带 `（条件）` 的章节在当前任务不涉及时直接删去。
- **单一权威与正向表达**：独立规格拆出后成为该内容唯一权威，`work.md` 只保留链接。只写已核实事实、可执行结论与真实缺口，不在段落末尾重复附加防御性免责套话。具体写法示例可按需参考 [按需写作示例](../docs/examples/document-quality/README.md)。
- **入口与消息片段**：工作区接入步骤见 [README](../README.md)，目标定位遵循 [上下文规范](../docs/context.md)；模板内相对路径统一从生成文件自身目录解析。[委派片段](fragments/delegation.md) 与 [结果片段](fragments/task-result.md) 仅用于多 Agent 任务提示和返回消息，不生成每任务的 `handoff.md` 或 `result.md`。
