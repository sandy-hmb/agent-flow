# 明确方案

## 输入

目标、验收、范围边界与已知约束。先读工作区入口与目标仓适用规则；仅入口缺失、多仓歧义或路径变化时读 [上下文规范](../../../docs/context.md)。已有有效方案直接复用；明确小改直接进入 `flow-execute`，不补造流程文档。

## 动作

- **先摸底核实现状**：定向只读核实相关源码、测试入口与已有说明；发现文档描述与源码实现不一致时先指明事实冲突，不把过时文档当现状。重要未知需独立深挖时先用 `flow-explore`。
- **决策导向澄清**：分清用户必需结果、必要技术措施与可延期的可选改善。只询问会改变目标、范围、关键方案、验收或外部影响的未决项，对比真实备选的兼容、成本与风险并给出推荐；低风险实现细节自行决定。
- **优先局部复用**：从现有改动点出发，局部直改能满足验收即停在局部。新增抽象或扩展旧机制时，须写明对应的当前需求或具体失败场景及局部改法为何不足，不为“以后可能用到”预埋设施。
- **写清不变边界与风险**：复用既有能力时明确适配点及保持不变的算法、状态、错误语义与副作用；仅对真实契约变化或副作用展开兼容与失败恢复，保留必要校验与事务保障，一次性迁移注明载体、操作方与下线条件。
- **拆解可验证交付**：仅按真实依赖、协作或风险拆任务，配置、测试、文档随所属交付合一；写明已核实路径、交付物、前置依赖与检查命令（复杂验证选择按需读 [验证规范](../../../docs/verification.md)）。规格细则直接链接设计或验收章节，严禁在计划中复述算法、字段或测试矩阵。
- **最小执行安排**：默认目标现有目录、单 Agent。仅在用户选择 worktree、多 Agent 或恢复非默认安排时读 [执行规范](../../../docs/execution.md)，记录目录、分工与整合验收位置；规划阶段不创建目录、不派发子任务。
- **按需落盘与原地自查**：仅跨会话或独立审阅时读 [文档规范](../../../docs/documents.md)——常规任务只维护一份 [工作记录](../../../templates/work.md)，关键技术取舍拆 [设计](../../../templates/design.md)，多任务协作拆 [计划](../../../templates/plan.md)，用户明确要求独立需求评审才用 [需求模板](../../../templates/requirements.md)。交接前删净多余复杂性并核对契约、依赖与反例覆盖，直接修原文，不另出检查报告。

## 产出

最小充分方案、可观察验收、必要的交付拆分与待决定项；简单方案直接回复即可。

## 停止与恢复

方案明确且已在授权内时可直接进入 `flow-execute`，无需重复审批；关键前提未决时只暂停受影响部分，其余独立授权部分可继续。接手恢复时核对权威方案与未关闭项，依据变化再修订。
