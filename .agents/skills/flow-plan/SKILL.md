# 明确方案

## 输入

目标、验收、范围与非目标、已有事实和约束。进入任务按 [上下文规范](../../../docs/context.md) 读取工作区入口并定位目标。已有有效方案直接复用；明确的小改不补造需求、设计和计划全套文档。

## 动作

- 先读当前资料，复杂请求简短回述目标、现状与本次要改变的部分。区分资料已有答案、需要调查的事实、用户需要决定的选择和可自行决定的实施细节；已有答案直接引用，缺事实先定向核实，重要未知需独立调查时使用 `flow-explore`。
- 只询问会改变目标、范围、关键方案、验收或外部影响的未决项，说明答案会影响什么；不把可自行决定的实现细节变成用户问卷。真实备选按兼容性、成本和风险比较并给出推荐，不为格式凑方案数量、问题轮次或额外审批。
- 选择最小充分方案，说明现状差异、不变约束、关键正常路径及相关失败处理、副作用和恢复，明确职责与真正跨任务的接口。区分已确认约束、建议方案、实施可自决空间和待用户决定项；具体内容按需使用 [设计模板](../../../templates/design.md)。复杂安全、迁移、性能、界面或接口文档按项目规则或已选专业能力处理，不引入尚无需要的设施。
- 以可独立验证和审阅的交付单元拆任务，只按真实依赖、协作或风险划分；需要的配置、测试和文档随对应交付归入任务，不按时长或文件数量凑任务。核实涉及的路径/模块，为每项写清范围、交付、直接依赖/接口、准确规格章节或验收引用，以及检查的方法、环境与预期观察；命令核实后才写。必要扩展的产物、前置、维护者和一致性检查纳入相关任务。已有规格只引用，不在计划复制算法、字段或完整矩阵。选择检查时按需读 [验证规范](../../../docs/verification.md)。
- 执行方式沿用有效授权，未选择时默认已确定目标的现有工作目录、单 Agent。用户选择 worktree、多 Agent 或需要变更/恢复安排时读 [执行规范](../../../docs/execution.md)，先核实目标再记录真实目录、分工、依赖、结果整合与最终验收目标；这里只形成安排，不创建 worktree、不派发 Agent。
- 只有需持久记录或独立审阅时读 [文档规范](../../../docs/documents.md)。优先复用已有记录，否则从 [工作记录](../../../templates/work.md)、[需求](../../../templates/requirements.md)、[设计](../../../templates/design.md)、[计划](../../../templates/plan.md) 中只选必要模板；已独立维护的规格和任务只引用，不双写。
- 交接前原地自查：另一实施者还得猜什么，猜错会影响什么？资料已有答案补入或引用，授权内细节注明可自决空间，关键用户选择回问。计划同时核对验收都有任务和检查、无额外范围、依赖与接口名称一致、相关失败有验证，实施者不必重做关键决策；发现问题修原文，不另建状态表、检查报告或审批。默认由当前 Agent 自查；独立只读审查只在获授权且实际风险需要时安排。

## 产出

必要的方案与取舍、验收方式、任务依赖、执行安排和待决定项。简单工作可直接回复；记录的安排不等于动作已发生，也不扩大实际授权。

## 停止与恢复

方案足以执行且授权已覆盖时可继续 `flow-execute`，不因换 Skill 重复审批。影响执行的关键选择未决时停在该边界，独立且已授权的工作可继续。接手先核对当前目标、权威方案及未关闭项；依据变化才修订并说明影响，不凭旧聊天重建计划。
