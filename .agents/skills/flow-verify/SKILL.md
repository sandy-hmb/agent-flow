# 核验结果

## 输入

当前目标与必要验收、实际改动、适用规则、已有检查和原始证据。进入任务按 [上下文规范](../../../docs/context.md) 读取工作区入口并定位目标。选择检查、判断复用及完成边界时按需读 [验证规范](../../../docs/verification.md)。

## 动作

- 先核对实际目标、目录与内容来源，对照验收看遗漏、额外范围、diff 和必要文档的一致性，再看测试结果。多 checkout 时按执行安排的最终验收目标核对，不默认以协调者当前目录为准。
- 对已有证据检查来源、输入、覆盖与当前适用性：代码、依赖、配置、测试输入、整合结果或共享资源变化可能使其失效。有效结果直接复用；仅对实际变化、新风险或覆盖缺口补验，不因换 Skill/Agent 机械重跑。
- 使用项目已有检查入口。报告真实命令、工作目录、结果及工具提供的执行/跳过信息；零测试、目标跳过或仅编译不能证明所需行为已验证，Mock 不代表真实数据库、鉴权或事务链通过。
- 核对子任务与扩展的实际目标、版本、产物及限制，不把 done、commit 或 success 当作验收。各分支局部通过不等于整合通过；核验最终输入期间暂停相关写入。独立成果则分别核对其版本与依赖。
- 必要验收缺工具、证据失效或失败时保留缺口，不为收尾改成可选。失败、环境不可用、未执行、未知和外部未验收分别表述。

## 产出

按验收给出已证实结果、未关闭项、限制与安全下一步，区分历史通过、当前实现/检查和外部上线。目标实现且必要证据充分、约定的必要扩展检查完成、无实质阻塞才可宣称完成；仅完成本地部分就明确如此。无需另写报告；确需独立交付时先读 [文档规范](../../../docs/documents.md)，选择 [验证模板](../../../templates/verification.md)，引用原报告而非复制日志。

## 停止与恢复

发现缺陷可回 `flow-execute` 做原授权内修复；纯核验请求不自动授权改代码。新范围、验收降低或新增外部影响需确认。缺口无法关闭时报告实际限制，不伪报通过。恢复先核对当前验收和证据输入是否变化，只补必要检查，不把历史结论直接当作当前结果。
