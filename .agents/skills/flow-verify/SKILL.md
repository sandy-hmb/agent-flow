# 核验结果

## 输入

当前目标与验收（代码审查时为指定分支或 diff 范围）、实际改动及已有检查证据。先读工作区入口与目标仓适用规则；仅入口或目标歧义时读 [上下文规范](../../../docs/context.md)，仅复杂证据复用、跨环境缺口或存量问题分流时读 [验证规范](../../../docs/verification.md)。

## 动作

- **核对范围与 diff**：对照权威验收检查实际验收目录和范围内完整改动（含新增未跟踪文件、修改与删除），核对遗漏、越界改动及关联文档一致性；多 checkout 按最终整合目标核对，核验期间暂停相关写入。
- **复用有效证据**：检查已有验证结果是否对应当前代码、配置与输入；仍然有效的直接复用，仅对新改动、分支整合新增风险或覆盖缺口补跑项目检查，不因换阶段机械重跑。
- **核实真实覆盖**：记录实际命令、目录、退出码及执行/跳过统计；零测试、目标跳过、仅编译或局部 Mock 不替代所需真实链路验证，子任务或扩展返回的 `done`/`success` 不替代产物核对。
- **分类处理发现**：纯核验或代码审查请求保持只读，不要求补造前置任务文档；已有实施授权时，本次引入缺陷直接回 `flow-execute` 修复。阻断验收的存量问题、范围外历史建议与环境证据缺口按 [验证规范](../../../docs/verification.md) 四分类披露，不为收尾降低验收要求。

## 产出

按验收直接给出已证实结果、未关闭缺口与安全下一步；目标实现、当前证据充分且无实质阻塞即可确认收尾，存在未执行的外部或环境检查时点明具体缺口即可，不重复堆砌免责套话。默认在回复中收尾，有 `work.md` 时原地覆盖其 `当前概览` 与最新 `实际验证`（替换已作废轮次）；仅在用户或外部流程明确要求独立交付验证报告时才读 [文档规范](../../../docs/documents.md) 并选用 [验证模板](../../../templates/verification.md)，引用原报告而非复制日志。

## 停止与恢复

原授权内缺陷直接回 `flow-execute` 闭环；新增范围、调整验收或外部操作需用户确认。缺口无法在当前环境关闭时如实保留限制；恢复核验先检查输入是否变化，只补受影响项。
