# worktree 执行参考

仅在用户选择 worktree 或恢复相关工作时读取。模式选择、执行安排与归属见 [执行规范](../../../../docs/execution.md)；多 Agent 另按 [多 Agent 参考](multi-agent.md) 处理。worktree 不要求多 Agent，也不授予其他 Git 操作权限。

## 输入与准备

- 从有效安排确认目标仓、拟复用/创建的实际路径、分支、基线 ref/commit、最终验收位置与保留边界；不默认 develop、test 或最近分支。
- 在正确仓核对分支/HEAD、worktree 列表、dirty、未完成 Git 操作与目录权限，可用 `git status --short --branch`、`git worktree list --porcelain` 等现有只读入口。不是 Git 仓或能力不足时说明限制，请用户选择可用方式，不伪称隔离成功或静默降级。
- 只在现有授权覆盖路径、分支与基线时复用或创建；需要 fetch、新目录或其他未覆盖影响时先确认。已有授权不因换子任务重复询问。

## 实施

1. 不覆盖已有目录/分支，不强制绕过分支占用，不自动 stash/reset。原 checkout 的未提交改动不自动转移；确需使用时先明确归属与转移方案。
2. 创建后核对实际工作根、分支和基线，再读取该 checkout 的适用规则并实施。依赖、被忽略配置和测试设施未必随目录存在，按项目已有方式准备；选择 worktree 不授权安装依赖、复制凭据或连接外部环境。
3. worktree 只隔离工作树，Git 公共配置、数据库、端口和构建缓存等仍可能共享。修改公共状态或共用测试资源需串行，或使用已确认的独立配置。
4. 默认在选定 worktree 保留成果；按安排在明确目录验收。需要整合时由指定负责者按已授权方式处理，commit、merge/cherry-pick、差异应用或目标分支变化各自核对授权，不把 worktree 选择当作一并批准。不自动处理归属不明的冲突。

## 产出、停止与恢复

返回实际路径、分支/内容来源、改动和检查位置、未关闭项及保留状态。计划里的路径不是创建成功证据。

创建结果未知时先查 Git worktree 列表和文件系统；目录已存在、分支占用或基线不符时停在冲突处，不覆盖、不重复创建。接手先核对现存 checkout、未完成改动与活动写入者；变更模式前停稳相关写入并保留成果。

不自动提交、推送、合回、建 PR 或删除 worktree/分支。清理须明确授权，且确认成果已保留、无活动写入者和未处理改动；任务结束不是清理授权。
