# worktree 执行参考

仅在用户选择 worktree 或恢复相关工作时读取。执行安排见 [执行规范](../../../../docs/execution.md)；组合多 Agent 时同读 [多 Agent 参考](multi-agent.md)。

## 输入与准备

- **确认基线与路径**：核实目标仓、拟复用或创建的路径、分支名、基线 ref/commit 及最终验收位置，不默认猜测 `develop` 或 `test` 分支。
- **只读核查现场**：用 `git status --short --branch`、`git worktree list --porcelain` 检查当前分支、现存 worktree、未提交改动及未完成 Git 操作；非 Git 仓或目录权限不足时报告限制，不静默降级。
- **核对授权边界**：仅在授权已覆盖目标路径、分支与基线时创建或复用；涉及 `git fetch` 或未授权父目录写入时先确认。

## 实施

1. **安全创建**：不覆盖已有目录或强行占用已检出分支，不自动 stash/reset；原目录 dirty 改动保留在原处，确需迁移时先确认方案。
2. **环境准备**：进入新 worktree 后核对实际根路径、分支与 commit，按项目已有方式准备本地配置或依赖（不擅自全局安装工具或复制敏感凭据）。
3. **注意共享资源**：worktree 仅隔离文件树，Git 公共配置、本地数据库、端口与缓存仍可能共享，涉及共享资源的测试需串行或隔离配置。
4. **保留与整合**：成果默认保留在该 worktree；需合回或整合时由指定负责者按已获准的 Git 方式处理，遇到归属不明的冲突先停下确认。

## 产出、停止与恢复

- 返回实际 worktree 路径、分支/HEAD、改动与检查结果及保留状态。
- 创建结果未知或遇目录/分支冲突时先查 `git worktree list` 与文件系统，停在冲突处不重复创建；恢复接手时先确认现存目录、dirty 状态与活动写入者。
- 任务结束不等于清理授权；删除 worktree 或分支须获明确授权，并确认成果已保留且无未处理改动。
