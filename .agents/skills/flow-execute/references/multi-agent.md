# 多 Agent 执行参考

仅在获准委派或恢复已批准的多 Agent 工作时读取。模式与最小安排见 [执行规范](../../../../docs/execution.md)；选择 worktree 时再读 [worktree 参考](worktrees.md)。多 Agent 不要求并行或 worktree。

## 输入与启动配置

- 核对宿主委派能力、目录可访问性以及用户对角色、数量、模型的约束。获准委派后先读取可用 profiles 与 notes，再选择配置；没有配置能力时明确采用宿主已有默认或用户指定配置，不编造 profile、不暗改模型。必须配置不可读时先报告阻塞。
- 主 Agent 负责协调、范围、主记录和最终结论；子 Agent 只处理分配任务，不扩展范围、不再委派、不接管整项工作，除非用户另行明确授权。
- `initialPrompt` 明确角色、目标、真实仓与 checkout、允许修改路径、直接依赖、适用规则、验收、验证入口及禁止副作用，不能只依赖 profile 名称或备注。只提供必要上下文，可按需使用 [委派片段](../../../../templates/fragments/delegation.md)，不复制全部历史或默认生成交接文件。

## 写入与依赖

- 同一 checkout 同时最多一个写入者，主 Agent 也计入；即使修改不同文件，实施与主记录更新也要串行。会写构建产物或共享测试数据的检查同样核对冲突。
- 共享 checkout 的实施任务轮流执行；不同 worktree 或独立仓的任务只有依赖与共享资源允许时才并行。不因独立目录存在就假定数据库、端口或 Git 公共状态独立。
- 只读分析/审查使用明确版本或稳定 diff；实现者仍在改同一输入时，不把审查当最终结论。依赖未完成可先分析，不用未经确认的产出实施后续依赖步骤。

## 回收与整合

- 子 Agent 返回实际修改位置、分支/内容来源、改动、检查命令/工作目录/结果、工具提供的执行与跳过数、证据位置、未验证项和阻塞。可按需使用 [结果片段](../../../../templates/fragments/task-result.md)；不要求每任务创建结果文件。
- 主 Agent 核对实际 diff、范围和证据，不以宿主 done、一次 commit 或“测试通过”替代核对。来源与输入一致就复用局部检查；仅对整合新增风险、内容变化或覆盖缺口补验。
- 独立 worktree 的代码不会自动汇总。实施前明确整合方式、负责者和最终验收目录/版本；涉及 commit、merge/cherry-pick、差异应用或新增目录时核对授权，不靠 reset、stash 或强推清场。独立交付则分别明确验收目标。
- 最终核验期间暂停相关输入写入；局部通过不证明整合通过。协调者维护唯一主记录，子 Agent 返回事实而不并发覆盖；最终结论交由 `flow-verify` 对照验收核对。

## 停止与恢复

启动/运行结果未知时，先核对已有 Agent、活动写入者和实际产出，不重复派发或直接接管。修正尽量复用原 Agent；无法确认旧写入者已停稳时，不启动第二个写入者，包括主 Agent 自行写入。

模式变化前收集结果、停稳写入并保留未完成改动；新会话从当前记录核实实际目录、运行事实和产出，不凭聊天记忆重新派发。必要时保留可用于查询的宿主运行 ID，不建设全局注册表。

宿主能力或授权不足时报告限制，请用户选择单 Agent 或其他可用方式，不静默降级或伪装已委派。只阻塞依赖该方式的工作，其他已授权且独立的工作可继续。
