# 多 Agent 执行参考

仅在获准委派或恢复多 Agent 工作时读取。模式选择与最小安排见 [执行规范](../../../../docs/execution.md)；组合使用 worktree 时同读 [worktree 参考](worktrees.md)。

## 输入与启动配置

- **读取宿主配置**：核对宿主委派能力、目录权限及用户对角色/数量/模型的约束。先读取宿主提供的角色配置与说明（如 Paseo 的 profiles 与 notes）再选配置；无命名配置时采用宿主默认或用户指定配置，必需配置不可读时先报告阻塞。
- **明确主从边界**：主 Agent 负责范围控制、主记录维护与最终验收；子 Agent 仅处理分配范围，不扩展任务、不再次委派、不接管整项工作。
- **写全启动提示**：按宿主接口（如 Paseo 的 `initialPrompt`）传入职责、目标仓与真实目录、允许修改路径、前置依赖、适用规则、验证入口及禁止副作用，可按需参考 [委派片段](../../../../templates/fragments/delegation.md)，不能仅靠 profile 名称或备注传递要求。

## 写入与依赖

- **单 checkout 串行写入**：同一 checkout 同时最多一个写入者（含主 Agent 及会改写构建产物/共享测试数据的检查），共享目录的任务轮流写入。
- **并行前提**：仅不同 worktree 或独立仓、且无前置依赖和数据库/端口/Git 公共状态冲突时才可并行。
- **稳定输入**：只读分析或代码审查基于明确 commit 或已停稳的 diff；上游依赖未确认前不启动下游写入。

## 回收与整合

- **结构化回收**：子 Agent 按 [结果片段](../../../../templates/fragments/task-result.md) 返回实际目录、改动文件、检查命令与统计、未关闭项及写入停止状态，不默认落盘每任务结果文件。
- **核对与分类**：主 Agent 核查真实 diff 与证据，按 [验证规范](../../../../docs/verification.md) 分类审查发现，不把一般建议直接派成修复任务；输入未变的局部证据直接复用。
- **分支整合验收**：独立 worktree 成果按已授权方式汇总到最终验收目录（不擅自 commit、merge、reset 或强推），暂停写入后用 `flow-verify` 补跑整合检查并由主 Agent 更新唯一主记录。

## 停止与恢复

- **未知状态先查现场**：派发或运行状态不明时，先查询现有子 Agent、活动写入者与文件改动；确认旧写入者停稳前不重复派发或由主 Agent 并发写入，后续修正优先复用原 Agent。
- **接手与能力受限**：跨会话恢复时凭主记录中的目录与宿主运行 ID 核实产出。宿主不支持委派或配置受阻时如实报告限制并请用户选择替代方式，不静默降级或伪装已委派。
