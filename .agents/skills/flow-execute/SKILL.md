# 执行改动

## 输入

已明确的目标与验收、允许范围及当前方案。先读工作区入口与目标仓适用规则；仅入口缺失、多仓歧义或路径变化时读 [上下文规范](../../../docs/context.md)。已有有效方案直接继续，无独立计划文件不阻塞。

## 动作

- **核对工作现场**：确认真实目录、可写范围与已有未提交改动（Git 仓核对分支、HEAD 与 dirty，非 Git 目录直接使用路径；多仓联调按上下游契约顺序分别核对各仓分支与检查）。默认单 Agent 在目标现有目录执行；仅选 worktree、多 Agent 或恢复非默认安排时先读 [执行规范](../../../docs/execution.md) 及对应的 [worktree 参考](references/worktrees.md) / [多 Agent 参考](references/multi-agent.md)。
- **按边界实施**：遵循已选改法与复用不变边界，原授权内的必要修复连续推进。若需超出已确认方案或授权边界改变原算法、事务语义、公开契约或运行权限，先说明原因与影响并按 `AGENTS.md` 确认，不顺带扩大重构；仅重要未知需独立深挖时转 `flow-explore`，关键方案推翻时回 `flow-plan`。
- **建立改动反馈**：修 bug 优先跑相关检查或复现以核实失败基线，修复后保留有价值的回归断言（未能复现时如实说明，不补造失败记录）；原因不明、修复无效或出现新异常时，先复核假设与当前证据，用最小检查区分可能原因，再决定下一处改动；新行为覆盖正常输入与关键反例；重构核对前后行为基线；文档核对来源、链接与接手可执行性。
- **局部检查与轻量闭环**：使用项目已有入口运行目标检查，修复本范围内的错误并记录命令、目录与真实结果。**单 Agent 常规小改可直接在此核对范围内完整改动（含新增未跟踪文件、修改与删除）及验收条件完成收尾**，无需机械切换加载 `flow-verify` 或 [验证规范](../../../docs/verification.md)；仅多任务/多分支整合、跨环境复杂证据复用或独立核验时转入 `flow-verify`。
- **原地更新记录**：仅需跨会话续作或维护正式文档时读 [文档规范](../../../docs/documents.md)（新建主记录用 [工作记录模板](../../../templates/work.md)）；迭代更新时原地覆盖 `当前概览`（5～8 行）与最新 `实际验证`，淘汰已作废轮次流水。

## 产出

实际修改的文件与内容、执行的检查命令及结果、实际未验证缺口与结果所在目录。

## 停止与恢复

范围、关键方案、验收或外部影响出现尚未获准的变化时补充确认；工具或环境缺失时如实报告缺口。操作结果未知时先查现场再决定下一步；暂停或接手时核实未完成改动、活动写入者与实际检查状态。
