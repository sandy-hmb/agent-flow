# 维护检查与行为试用

本目录不运行工作流。格式和链接通过只能证明公共资源可读取，不能证明 Agent 一定遵守指令。

## 可重复的维护检查

在仓根运行：

```bash
python3 -B -m unittest discover -s tests -p 'test_*.py' -v
```

仅需标准库，检查四个核心 Skill、简短单行元数据、五份规范、八模板/两片段、当前使用的 Markdown 内联链接、围栏/空白、公共路径、共享入口与私有任务数据隔离。不请求网络，也不读取 `.workspace` 中的私有内容。

这些测试约束本项目约定的结构，不对用户产物执行强制格式验证，不判断文本语义或用户实际授权。

## 独立前向试用

使用 [场景说明](scenarios.md) 在临时目录提供原始资料，由独立 Agent 读取实际发布文档完成请求。不要把预期答案、发现的问题或实现建议放进试用提示。主协调者检查原始 diff、文件清单、来源与真实命令，再比较行为和验收。

接入与路由回归场景覆盖默认单仓、多仓路由和默认目标、显式目标、任务记录、资源根维护、歧义和失效路径，以及其他入口绑定、未初始化直用和宿主默认配置。观察 Agent 实际读取和修改了哪些文件，不以关键词匹配或维护测试通过代替行为验证。

文档质量试用使用场景 1、11–14，覆盖资料充分、关键歧义、设计接手、已有设计的引用式计划、必要扩展与轻量小修。这些是准备与观察方法；新增场景未运行前不得列为已通过。

需要比较规则版本时，在相同模型、宿主、权限、原始资料和任务输入下，分别使用对应资源版本及独立新会话，做少量独立重复；不把前一次答案、点评或示例输出带入提示。记录实际模型/宿主与版本、输入关联、重复次数、文件/工具轨迹和产物。检查重要遗漏、无依据猜测、有价值或多余的补问、交接执行性、相互矛盾，以及轮次、工具调用或宿主可得的时间/token 成本；不以字数、关键词或更短输出判定质量。接手试用可另请一个未参与规划的只读实施者评价剩余猜测，不新增真实实施授权。条件不同或轨迹缺失时披露限制，样例观察不外推为全部行为保证。

初次实现期间已经实际试用的记录会列在此处。它们是特定模型、宿主和样例下的观察，不代表所有宿主都通过，也不是每次运行维护测试自动重放的结果。临时资料不承诺长期保存；需要审计时由项目明确留存。

| 场景 | 初次观察 | 覆盖边界 |
| --- | --- | --- |

## 接入与路由的本轮观察

在隔离临时目录中提供完整资源副本、工作区入口、少量业务源码和必要项目规则。两个独立试用者分别处理 11 个只读变体及 1 个小改任务；每个变体单独提供请求与路径，执行时重读对应入口。部分变体由同一 Agent 连续处理，尚未验证每变体独立新会话的效果。以下观察不代表真实团队仓库或所有宿主均已接入。

| 输入 | 实际观察 | 覆盖边界 |
| --- | --- | --- |
| 默认入口只配置 billing | 读取唯一仓规则和费用源码，解释 2% 加固定费用 1 | 只读；没有执行费用计算或核对产品口径 |
| 多仓索引，用户指定 console | 读取 console 权限源码，未读取默认 billing 源码 | 验证显式目标覆盖默认；未单独运行同时覆盖冲突任务记录的变体 |
| 当前任务记录指向 console，默认 billing | 从指定记录文件位置解析目标路径，继续 console 调查 | 未更新记录，不涉及历史记录搜索 |
| 用户明确维护 Agent Flow 自身 | 以资源根为目标，读取四个 Skill 解释用途 | 只读解释；未修改工作流文件 |
| 两仓无默认且目标不明 | 在入口处询问选择哪一仓，未读取两仓源码 | 未单独运行两条路由同时命中的变体 |
| 已选仓路径不存在 | 报告配置路径缺失，未寻找旁边的替代仓 | 不涉及目录权限不足或符号链接变化 |
| 未初始化，用户指定 billing | 直接读取指定目标，解释 5% 费用源码 | 未创建工作区入口 |
| 管理界面路由 console，默认 billing | 采用路由目标，未读取 billing 源码 | 单一路由，未运行跨仓联调任务 |
| 多仓未命中路由，默认 billing | 采用默认目标，解释 3% 费用源码 | 只读，不验证修改授权 |
| 显式绑定 config/workspace.md | 从绑定文件解析 console 路径，未读取默认入口或目标内未引用的同名文件 | 本地绑定，不证明宿主自动发现行为 |
| 显式入口缺失，默认入口有效 | 报告缺口并停止，未回退到默认入口或业务源码 | 等待提供正确入口或明确撤销绑定 |
| 从资源目录请求修复 clamp | 通过唯一仓索引进入 calculator，仅改一行实现；已有 3 项测试先失败后通过，主控复跑通过 | 默认目录、单实施者、无 Git；未生成流程文档或修改入口 |

协调者对照试用者返回的读取文件清单和命令轨迹，并核对 368 个样例文件的 SHA-256 与新增文件清单：只有获准的 `execute/calculator/textops.py` 改变，没有新增文件。文件哈希支持写入边界结论；读取边界依据工具轨迹，不能仅凭文件未变化推断没有读取。未涉及的业务仓和无关目录没有出现在返回的读取轨迹中。

仍未实际覆盖：每变体独立新会话、宿主默认角色配置场景、跨宿主安装、跨仓路由、子 Agent 启动 unknown/进程中断恢复、worktree 冲突与清理、多个分支整合后的完整测试、共享数据库/端口的并发冲突。这些有明确操作边界和可演练场景，但不能记为已验证。没有执行真实外部操作或业务平台接入。

## 文档质量优化的本轮观察

以 `0be077f` 的完整资源快照为基线，Paseo 使用 `codex/gpt/gpt-6-luna`、medium、auto-review 配置，在独立临时目录进行 13 个新会话：基线与首版优化各完成设计、计划各两次；最终模板再做两次计划和一次设计复测；另各做一次轻量小修与关键歧义观察。各版本使用相同原始业务资料，任务提示只随资源和目标路径变化。中断前另有两个 native 样本，未混入此组对照。

主协调者读取实际产物、核对原始输入与资源快照的哈希及新增文件，独立审查者只读检查产物。所有文档试用只新增指定文档；小修仅改变获准源码，歧义观察未写文件。部分宿主活动仍带父会话主题摘要，歧义回复也出现任务外的 Superpowers 话题，因此不能称为严格无历史盲测或纯因果对照。哈希支持写入边界，不能证明未越界读取；只抽查了部分宿主活动，未量化可靠的时间/token 成本。

| 对象 | 实际观察 | 仍有的限制 |
| --- | --- | --- |
| 设计 | 基线和优化样本均能解释部分写入与两阶段处理；优化样本显式描述现状、不变约束、正常/失败路径和实施选择，未引入额外平台 | 旧有效数量输入的兼容解释及实施选择/待确认的边界仍不稳定；最终设计只复测一次，不能宣称兼容问题已解决 |
| 计划 | 首版仍有规格复述，且一份将测试留到实现后独立补齐；据此补充紧凑正向写法及有区分力的反例提示。最终两份均把测试归入交付，并明确预置数据、前部合法行和后部非法行，异常后数据完全不变 | 两份仍复述部分规格；一份把仅表头误写为空表头，与批准设计及自身检查冲突。没有实施样例，不能解释为行为测试通过或可直接批准 |
| 必要扩展 | 各份计划均安排实现后生成本地 handoff，并核对最终实现与权威设计；未提前生成或发布 | 未真实生成 handoff，未覆盖缺前置等全部扩展变体 |
| 轻量小修 | 只改 `clamp` 源码，不建流程文档，目标 3 项测试通过；主控分别运行原始样例和修复样例，原始 3 项中 1 项失败，修复后 3 项通过，均无跳过 | 试用 Agent 未在修复前运行失败测试；主控事后对照不能冒充该 Agent 先观察失败，不证明所有任务遵循先复现习惯 |
| 关键歧义 | 回复识别整批拒绝与部分成功的产品选择，说明后果并给推荐，未写文件或先实施 | 只观察首轮，未提供选择后续作；回复有父话题污染，不支持完整澄清流程已验证 |

原始产物、输入哈希和局部测试输出保留在组织者的临时目录，公共仓不包含这些临时资料，也不保证其长期可用。以上是有限模型、宿主和样例的真实观察；模板修订、静态审查无明确问题与 Agent 产物全部正确是不同结论。未验证跨模型稳定性、真实业务仓接手或统计上的质量提升，不因存在残余就继续为个案累加通用规则。

## 范围控制优化的本轮观察

本轮新增的范围控制规则在两个独立临时样例中试用：管理员入口复用现有渲染/授权/状态/审计能力，一次性迁移因载体和操作员未定而保持为待决定项；审查样例将绕过租户过滤的本次缺陷列为阻断，将未改动的历史内存风险列为范围外建议，将通用序列化框架列为拒绝扩展，将真实 PostgreSQL/部署权限列为证据缺口。两次试用均只写指定方案或审查结果，未实施、未访问环境或搭建替代设施。

试用使用 `codex/gpt/gpt-6-luna`、medium、auto-review 和冻结的工作流快照；输入哈希核对原始资料未变、每个目标目录只新增允许文档。独立审查者检查冻结的 9 个公共文件 diff，未发现规则冲突、范围扩张或隐含授权；维护测试与链接检查仍需主控最终执行。父会话摘要可能出现在宿主活动中，样例各仅一次，不能证明跨模型稳定性或已消除所有过度实现。

## 局部方案约束的本轮观察

针对用户过度设计反馈，Paseo 探索配置 `codex/gpt/gpt-6-luna`、medium、auto-review 在独立临时目录完成两个优化后方案，均读取实际工作流资源：固定 CSV 两列导出只建议在现有函数中按键取值、复用 writer 和测试，未新增通用层；整批入账复用现有事务 API，保留金额校验、异常传播、回滚及后部失败检查，未增加补偿设施。后者因资料缺少实际调用方和测试夹具而保留事务嵌套与检查方式未知，未实施或执行行为测试。

另有一个相同局部任务的基线样本，虽也选择直接改动，但宿主活动显示未读取指定工作流，因此不构成有效前后对照。主控读取真实方案并核对三个目录只新增指定方案、原始输入未变；独立审查未发现公共规则问题，但指出局部样例将 README 的缺键异常要求误作源码已有行为，未识别资料冲突，不能把该方案视为事实全对。哈希不能证明读取边界，Paseo 活动还带父主题摘要。每个优化样例只观察一次，没有用户真实失败方案，不据此断言根因已证实、过度设计已消除或跨模型有效；样例资料保留于临时目录，不承诺长期可用。
