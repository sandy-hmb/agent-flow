# 维护检查与行为试用

本目录不运行工作流。格式和链接通过只能证明公共资源可读取，不能证明 Agent 一定遵守指令。

## 可重复的维护检查

在仓根运行：

```bash
python3 -B -m unittest discover -s tests -p 'test_*.py' -v
```

仅需标准库，检查四个核心 Skill、简短单行元数据、五份规范、八模板/两片段、当前使用的 Markdown 内联链接与 `#anchor` 锚点、围栏/空白、公共路径、共享入口与私有任务数据隔离。不请求网络，也不读取 `.workspace` 中的私有内容。

这些测试约束本项目约定的结构，不对用户产物执行强制格式验证，不判断文本语义或用户实际授权。

## 独立前向试用方法

使用 [场景说明](scenarios.md) 在临时目录提供原始资料，由独立 Agent 读取实际发布文档完成请求，不把预期答案或实现建议放进提示。协调者核查原始 diff、新增文件清单、读取/命令轨迹与真实退出码，不以关键词匹配代替行为观察。

比较规则版本时，在相同模型、宿主、权限和原始输入下使用独立新会话对照，检查：

- **读取与写入边界**：单仓快路径是否跳过不必要的规范预读，多仓路由是否仅读取涉及仓，是否仅修改获准路径。
- **方案与文档质量**：是否识别文档描述与源码现状的冲突，是否优先局部复用而非过度设计，`work.md` 多轮更新是否原地覆盖 5～8 行概览与最新验证而非追加流水账，计划是否通过规格链接避免复述设计。
- **核验与分流**：是否区分真实检查、Mock 与环境缺口，是否将审查发现按本次缺陷、阻断存量问题、可选建议与证据缺口分类处理。

## 已完成场景观察汇总

以下为特定模型与宿主（Paseo `codex/gpt/gpt-6-luna` 等）在临时隔离目录中的实际观察汇总，不代表所有宿主或每次单测自动重放的结果：

| 场景维度 | 实际观察结论 | 已知限制与未覆盖项 |
| --- | --- | --- |
| 默认单仓小修与隔离实现（场景 1、4、7） | 仅改目标源码并通过局部测试，不建多余流程文档；worktree 隔离保留源目录 dirty，多 worker 各自限定目录 | 偶有样本未在修复前先运行失败测试；未覆盖多分支合并后的真实共享数据库冲突 |
| 只读调查与证据核验（场景 2、3、6） | 区分计算事实与未知口径，未执行日志中恶意指令；拒绝用 staging 报告关闭 test 必要验收，`local-evidence` 仅只读核对指定文件 | 仅针对本地样例，未连接真实远端服务 |
| 接入与多仓目标路由（场景 8，12 个变体） | 368 个样例文件哈希核对仅获准文件改变；显式目标、任务记录、路由与默认目标优先级符合预期，显式入口或路径缺失时直接报告并停止 | 部分变体由同一会话连续执行，尚未逐变体全量跑独立新会话；未覆盖跨仓联调写入 |
| 设计交接与引用式计划（场景 5、11–14） | 设计显式交代不变约束、正常/失败路径；计划将测试归入交付并明确反例，未提前触发扩展写操作；关键歧义先说明取舍并推荐 | 少数计划样本仍残留局部规格复述，或未识别样例 README 与源码现状的细微冲突 |
| 局部方案与审查分流（场景 15、16） | 局部导出直接复用现有函数与事务，未引入策略层或补偿平台；审查按本次缺陷、阻断存量问题、范围外建议和环境缺口四分类处理 | 单模型有限样本观察，不能外推为所有模型或真实复杂仓库的统计保证 |

仍待演练的边界：单仓快路径下跳过 `docs/context.md` 与 `docs/verification.md` 的轨迹核对、多轮迭代下 `work.md` 概览与验证的原地覆盖防膨胀、长会话上下文压缩后的现场恢复、子 Agent 启动状态未知/中断恢复，以及跨仓联调的顺序验证。
