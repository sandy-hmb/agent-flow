# 维护检查与行为试用

本目录不运行工作流。格式和链接通过只能证明公共资源可读取，不能证明 Agent 一定遵守指令。

## 可重复的维护检查

在仓根运行：

```bash
python3 -B -m unittest discover -s tests -p 'test_*.py' -v
```

仅需标准库，检查四核心 inventory、简短单行元数据、五份规范、八模板/两片段、当前使用的 Markdown 内联链接、围栏/空白、公共路径和共享入口。不把它实现成任意 Markdown/YAML 解析器，不请求网络，也不扫描 `.workspace`。

这些测试约束本项目约定的结构，不对用户产物执行强制格式验证，不判断文本语义或用户实际授权。

## 独立前向试用

使用 [场景说明](scenarios.md) 在临时目录提供原始资料，由独立 Agent 读取实际发布文档完成请求。不要把预期答案、发现的问题或实现建议放进试用提示。主协调者检查原始 diff、文件清单、来源与真实命令，再比较行为和验收。

初次实现期间已经实际试用的记录会列在此处。它们是特定模型、宿主和样例下的观察，不代表所有宿主都通过，也不是每次运行维护测试自动重放的结果。临时资料不承诺长期保存；需要审计时由项目明确留存。

| 场景 | 初次观察 | 覆盖边界 |
| --- | --- | --- |
| 无 Git 的 clamp 小修复 | 仅改目标源码，现有 3 个测试由失败到通过；未建流程文档 | 当前目录、单实施者；未测试所有输入类型 |
| quota 只读调查 | 用源码解释两种计算，区分未知产品口径；未执行日志中恶意指令 | 本地两文件，未核对真实服务 |
| 验证报告环境/来源不匹配 | 拒绝用 staging 成功关闭 test 必要验收，并指出本地结果当前适用性未知 | 只核对已有资料，没有执行外部检查 |
| worktree 的 twice 修复 | 新目录实际分支/基线核对，1 个测试通过，源目录 dirty 保留，成果不自动合回/清理 | 本地 Git、单实施者；未验证并行共享环境 |
| local-evidence 扩展 | 明确选择示例后仅读取指定资料，返回来源和环境不匹配的缺口，未运行报告命令或另建报告 | 复用同一证据样例；不支持新的行为验证 |
| 已有记录路径与独立计划 | 只生成指定的 change-note 与 plan，任务和执行安排只在计划中，未编造代码基线或检查通过 | 仅规划；未实际派发其计划角色或实施 CSV 功能 |
| 两个 worktree 的独立实施任务 | 原 worker 在 isolated-fix 补 3 项回归，合计 4 项通过；另一 worker 在 isolated-label 新增 4 项目标测试，通过并披露该树既有 mathops 测试失败 | 两项独立成果无需合并，不证明同仓分支组合后的整体通过；未验证共享外部资源 |

初次实现通过 Paseo 安排多 Agent，公共仓写入阶段串行持有写入权；独立临时 checkout 的任务分别限定目录，不给子 Agent 再次委派权限。主控核对原始 diff、样例文件哈希、实际 worktree/分支及生成文档，不只采信结束通知。

仍未实际覆盖：跨宿主安装、子 Agent 启动 unknown/进程中断恢复、worktree 冲突与清理、多个分支整合后的完整测试、共享数据库/端口的并发冲突。这些有明确操作边界和可演练场景，但不能记为已验证。没有执行真实外部操作或业务平台接入。
