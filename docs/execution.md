# 执行方式与归属

仅在用户选择非默认方式（worktree、多 Agent）、变更执行模式或恢复相关现场时读取；常规任务默认在目标现有目录由单 Agent 直接执行（目标存在歧义时先读 [上下文规范](context.md)）。

## 两个独立选项

| 位置 | 协作 | 约束 |
| --- | --- | --- |
| 目标现有工作目录 | 单 Agent | 默认方式，直接在已授权目录实施与检查 |
| worktree | 单 Agent | 仅隔离工作树，不增加执行者，不自动隔离共享数据库或端口 |
| 目标现有工作目录 | 多 Agent | 只读分析/审查或串行轮流实施；同一 checkout 同时最多一个写入者 |
| worktree | 多 Agent | 无依赖且无共享资源冲突时可并行；每个 checkout 同时仍仅一个写入者 |

位置与执行者相互独立：多 Agent 不强制建 worktree，选 worktree 也不自动委派子 Agent；多仓任务本身目录独立，无需为协作额外新建 worktree。写入者包含主 Agent、主记录维护者及会改写共享产物的检查命令。模式选择不隐含 commit、push、merge 或清理目录权限。

## 最小安排，只维护一处

非默认方式在独立 `plan.md` 或 `work.md` 中择一权威维护（另一处只链接），仅记录当前模式必需项：

- 目标仓、真实工作目录；使用 worktree 时注明基线、分支名及属于“拟创建”还是“已核实存在”。
- 各角色的任务范围、前置依赖与允许写入路径。
- 独立验收位置，或多分支成果的整合方式、负责方与最终验收目录。
- 已获准的 Git 操作与成果保留边界（恢复需查询时附活动宿主运行 ID）。

## 按所选方式进入参考

- **选 worktree**：读 [worktree 执行参考](../.agents/skills/flow-execute/references/worktrees.md)，核实基线、dirty 隔离、共享资源与保留恢复。
- **获准委派**：读 [多 Agent 执行参考](../.agents/skills/flow-execute/references/multi-agent.md)，先读取宿主角色配置与说明（如 Paseo 的 profiles 与 notes），明确启动提示、单写入者串行与结果回收。
- **组合使用或异常处理**：组合模式同时适用两份参考；宿主能力不足或状态不明时先查现场、停稳写入并报告限制，整合后的验收边界见 [验证规范](verification.md)。

能力不足、运行结果未知或模式变化时按相应参考先核对现场、停稳相关写入并保留成果，不静默换模式、不重复创建/派发。最终证据对应所选验收目标，不默认对应协调者恰好所在目录；整合后的必要核验见 [验证规范](verification.md)。
