# 执行方式与归属

仅在选择非默认方式、模式变化或相关恢复时读取。先按 [上下文规范](context.md) 确定目标，默认在该目标的现有工作目录由单 Agent 执行；无 Git 的任务不编造分支信息。

## 两个独立选项

| 位置 | 协作 | 约束 |
| --- | --- | --- |
| 目标现有工作目录 | 单 Agent | 默认，直接在已授权目录实施与检查 |
| worktree | 单 Agent | 用户选择隔离位置，不增加执行者 |
| 目标现有工作目录 | 多 Agent | 可分析、审查或轮流实施；同一 checkout 同时最多一个写入者 |
| worktree | 多 Agent | 可在依赖与共享资源允许时并行；每个 checkout 仍仅一个写入者 |

多 Agent 不等于并行，worktree 不等于多 Agent。已有独立仓不为协作再建无用 worktree。写入者包含主 Agent、记录维护者及会改变共享输入的检查，不因修改不同文件而豁免。

用户当前明确选择优先，其次沿用有效执行安排；选择 worktree 前先核实目标仓。项目建议、工具可用或模板字段不构成创建目录或委派授权。已批准的同一范围安排不因换 Skill/子任务重复确认；改变方式、新增仓/目录或整合动作未被覆盖时才补充确认。计划只记录安排，执行才核对实际状态并采取已授权动作。

## 最小安排，只维护一处

简单任务可在回复说明；跨会话、多个执行者或多个 checkout 时，写入现有工作记录。已有独立计划则以计划为权威，工作记录只引用。只保留当前选择需要的信息：

- 目标仓、真实工作目录；worktree 的基线、分支，以及拟创建还是已核实存在。
- 单 Agent 或协调者/实施者/审查者的范围、依赖、允许修改路径和必要并行上限。
- 每个任务如何取得结果；独立产物各自验收，需组合则明确整合方式、负责者和最终验收目录/版本。
- 本次授权涉及的 Git 操作与成果保留/清理边界；未涉及的操作无需逐项填“否”。选择模式不授权 commit、push、合并或删除。

执行安排保存在上述权威位置；活动任务的宿主 ID 仅在恢复确有需要时记录，便于核对现有执行者与产出。

## 按所选方式进入参考

- 选 worktree：读 [worktree 执行参考](../.agents/skills/flow-execute/references/worktrees.md)，处理真实目录、基线、现有改动、保留与恢复。
- 获准委派：读 [多 Agent 执行参考](../.agents/skills/flow-execute/references/multi-agent.md)，先读宿主提供的角色配置及说明（如 Paseo 的 profiles 与 notes），再选择配置并明确角色、依赖、唯一写入者及结果回收。
- 两者组合时两份均适用，不在本规范重复 Git 或宿主操作步骤。

能力不足、运行结果未知或模式变化时按相应参考先核对现场、停稳相关写入并保留成果，不静默换模式、不重复创建/派发。最终证据对应所选验收目标，不默认对应协调者恰好所在目录；整合后的必要核验见 [验证规范](verification.md)。
