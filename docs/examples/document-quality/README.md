## 2. 可交接设计

教学输入：已读取样例仓 `src/importer.py`、`src/store.py` 和 `tests/test_importer.py`。用户已确认同步 CSV 导入，金额可为零，任一数据行错误则整批拒绝；无需异步任务或发布。以下正文作为本例唯一设计，后面的计划只引用它。

### 目标、依据与验收

现状为逐行解析后立即调用 `store.insert`，坏行前的数据可能已经写入。已确认本次改为全量校验后一次持久化；保留现有成功返回值 `imported_count`，不改变其他导入格式。依据为上述三个样例文件及用户的已确认选择，不代表任何真实仓库事实。

- A1：合法 CSV 全部写入，返回写入条数；只有合法表头、无数据行时返回 0。
- A2：任一数据行无效时返回行号与原因，已有数据不变；消费方仍能捕获现有 `ImportError`。
- A3：写入失败时不保留本批次数据，异常继续交给现有调用方处理。

### 所选方案与取舍

推荐先解析为内存记录列表，再在现有存储事务中一次写入。与逐行写入后补偿相比，可沿用现有事务、错误路径更少；代价是占用与批次大小成比例的内存。样例的已确认上限为每批 1000 行，当前不需要队列或临时表。推荐尚不是实施授权；本教学输入已单独给出允许规划的范围。

<a id="design-contract"></a>
### 正常路径与接口

`importer.parse_csv(text)` 提供记录列表，由导入入口调用；数据行只接受 `name`、`amount` 两列，`name` 去首尾空白后非空，`amount` 以十进制解析且非负，零有效。返回记录使用现有存储记录类型，不经过二进制浮点转换。列集合不符时在写入前返回格式错误。

导入入口把解析结果传给 `store.insert_batch(records)`；该接口由存储模块提供，返回写入条数，承诺同一事务全部写入或回滚。内部循环写法和局部变量命名由实施者决定。

<a id="design-failure"></a>
### 失败、副作用与恢复

解析失败抛现有 `ImportError`，数据行号从首条数据行为 1 计数，存储接口不得被调用。存储失败由 `insert_batch` 回滚后原样抛出。成功会新增记录，本例没有去重契约；失败后只能在确认未写入时由调用方决定重试，不增加自动重试。

<a id="design-checks"></a>
### 验证方向与未决项

A1 核对零金额、正常批次和仅表头输入；A2 核对后部坏行、负金额、无效列及调用前后存储快照；A3 用样例已有的事务失败注入能力核对回滚。测试入口已核实为标准库 unittest，具体执行责任见计划。样例关键选择已确认，无待用户决定项；未要求新增幂等、异步或发布设施。

## 3. 引用式计划

教学输入：沿用上一节设计，组织者已核实其中三个源码/测试路径及样例的 unittest 入口；本例只规划，不派发、不执行命令。以下引用在同文件中可直接定位，不另造 requirements 文件。

### 目标与安排

在 `/work/csv-demo` 当前目录由单 Agent 实施，不提交。规格以 [示例设计](#design) 为唯一依据，以下两个任务按接口依赖串行；主记录只引用任务标识并维护进展。

### P1：纯解析交付

范围为 `src/importer.py` 的解析入口与 `tests/test_importer.py` 的对应回归。交付可独立调用的 `parse_csv`，直接依赖为现有存储记录类型，无前序任务。按 [正常路径与接口](#design-contract)、[解析失败边界](#design-failure) 及 [A1/A2 的验证方向](#design-checks) 实施，不在计划重写金额规则或列定义。

实施者在该样例目录运行已核实命令 `python3 -B -m unittest discover -s tests -p 'test_importer.py' -v`，核对解析返回值、错误定位及未调用存储的观察；预期正常与反例断言都通过。该任务不宣称覆盖事务回滚。

### P2：原子持久化与入口接入

范围为 `src/store.py`、`src/importer.py` 的入口连接及对应测试。交付 `insert_batch` 与完整导入路径，直接依赖 P1 的 [parse_csv 返回契约](#design-contract) 及现有事务能力；按 [写入与恢复边界](#design-failure) 和 [A1–A3 的验证方向](#design-checks) 接入，不重新定义契约。相关测试及既有调用说明随此交付更新，不另拆文档任务。

实施者在同目录运行已核实命令 `python3 -B -m unittest discover -s tests -v`，预期全量通过；核对成功返回、后部错误时快照不变、注入写入失败后事务无残留。P1 的有效解析证据可复用，整合检查仍覆盖 P2 新增风险。

### 整体验收与依赖

最终以该目录实际改动对照 [A1–A3](#design)，由核验者核对 diff、测试覆盖和真实结果。计划不记执行状态或预填通过；输入变化时按影响补验。没有待满足的外部前置，真实实施前仍须核对当前现场与授权。
