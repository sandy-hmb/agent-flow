# 扩展约定

仅在选用、维护扩展或处理多输出冲突时读取；在工作区入口或项目规则中声明触发条件，未命中的扩展不加载、不初始化。

## 三种补充方式

| 方式 | 做法 | 示例 |
| --- | --- | --- |
| 规则补充 | 在项目规则中写明适用目标/目录、约束和按需读取入口 | 修改数据库迁移时读取项目已有迁移规范 |
| 能力扩展 | 选择有明确输入、产出和停止条件的 Skill，优先复用已有能力 | 核验本地报告时读取 local-evidence，并提供报告路径和当前验收 |
| 流程组合 | 在现有任务记录中写明已选能力的使用条件、前置事实和结果依赖 | 接口变更核验后，按用户选择准备客户端交接资料 |

已纳入本项验收的扩展，其必要产物、前置条件、维护者及与主规格的一致性核对直接归入相关交付任务，引用扩展自身契约，不另建独立计划或抄写专业手册。

## 扩展声明与写入边界

- **最小声明**：说明触发条件、所需输入与工具、读写边界、产物路径与维护者、失败恢复方式。选用扩展不隐含安装工具或外部写操作授权。
- **专业模板与冲突仲裁**：专业文档模板放在扩展自身 `assets/templates/`，遵循 [文档规范](documents.md) 按需读取；扩展只写获准产物，不覆盖已批准主规格。多能力拟写同一路径或规则冲突时，先明确唯一维护者与顺序，不静默覆盖。

## 结果交接与失败处理

用于验收或下游依赖的扩展返回简洁文本事实（不强制新建回执文件）：

- 实际目标、工作目录/环境与来源版本（未核实标明未知）。
- 执行动作、真实结果、覆盖边界与产物/证据位置（外部动作附请求或构建标识）。
- 未关闭缺口、负责方与安全下一步（有副作用的扩展须说明结果未知时的查询核对方式与禁止盲目重试的动作）。

协调者核对产物与验收覆盖后合入主记录；明确纳入验收的扩展缺失或失败时保留缺口，完成判断见 [验证规范](verification.md)。需只读核对已有本地报告时，可按需选用 [local-evidence 示例](examples/local-evidence/SKILL.md)。
