# 验证与完成判断

选择检查、解释复杂证据、复用结果或判断完成时读取。沿用目标项目的检查入口，围绕当前验收选择最小充分验证，复用仍然有效的结果。

## 从验收选择检查

先核对当前目标、权威验收、实际目录和改动，检查遗漏、额外范围、diff 及必要文档的一致性，再判断证据是否充分。测试通过不能替代目标符合性；独立审查仅在用户选择、项目规范或实际风险要求时增加。

沿用目标项目现有检查入口，按变化行为、兼容影响、失败分支和独有风险选择最小充分检查。文档可用来源/链接/结构与场景核对，行为变更需要相应行为证据；公开接口关注消费方与兼容性，不因此强制生成领域文档。缺环境不擅自安装、搭替代设施或访问新环境。

## 证据能证明什么

记录或引用实际检查的命令/方法、工作目录、输入来源、覆盖、结果和限制；版本无法取得时明确未知，不用虚构 commit 补齐。工具有执行数、跳过数等信息时如实核对，没有就不编造计数。

- 零测试、目标跳过、仅编译不能证明本来需要的行为通过。
- Mock 只支持其隔离范围，不证明真实数据库、鉴权链或事务结果。
- 日志/报告存在、工具返回 success、子 Agent 声明完成或一次 commit，都不是当前验收已关闭的充分证据。
- 检查失败、环境不可用、未执行、未知、历史通过和外部未验收分开表达；未知不能写成失败，也不能写成通过。

原始证据留在原来源。人工验证说明只维护一处，工作记录保存当前结论和引用，必要时用 [验证模板](../templates/verification.md) 独立交付，不为收尾复制另一份报告。

## 复用与失效

复用前确认目标、目录、来源、输入和覆盖对应本次验收。代码、依赖、配置、测试输入、整合结果或共享资源变化可能使结果失效，按实际影响补验；不因切换 Skill/Agent 重跑，也不靠 commit 相同证明所有输入未变。仅核对与当前验收有关的输入。

子任务/扩展返回后核对实际产物与限制，拒绝目标或版本不匹配的“成功”。多 checkout 时以执行安排的最终目录/版本为准，核验期间暂停相关输入写入。局部通过不证明整合通过；只补整合新增风险与覆盖缺口，独立成果分别验收。

## 缺口与完成

必要检查缺工具、失败、未执行或旧结果失效时，保留缺口、影响、负责方及安全下一步。已约定必要扩展检查不能为求收尾改成可选；取消要求必须有真实范围调整依据，不伪装成通过。可选检查失败不阻塞无关目标，但如实披露其影响。

只有目标实现、当前证据充分、必要扩展检查关闭且无实质阻塞，才能宣称本项完成。本地实现、当前检查、外部验收和上线是不同事实；外部动作不在范围内时不加门槛，已在验收内时不能忽略。只做完本地部分，就明确本地结果和外部待办。

核验发现缺陷：已有实施授权内可继续修复；纯核验请求不自动授权修改。新范围、降低验收或新增外部影响须核对授权，结果未知先查询，不盲目重放。
