# 验证与完成判断

仅在复杂证据复用、跨环境或多分支整合核验、存量问题分流或完成边界存疑时读取；单仓常规局部检查与验收收尾直接按当前 Skill 执行。

## 按改动类型选择检查

- **先查目标符合性，再看测试**：先对照验收核查实际目录、diff、是否偏离既定复用边界或引入越界改动，再选用项目现有检查入口覆盖核心变化与风险。
- **匹配反馈证据**：修 bug 核对问题复现与回归（未观察到修复前失败时如实说明，不补造失败过程）；新行为覆盖正常输入与有区分力的反例；重构对比改动前后行为基线；文档核对来源、链接与可接手性（影响 Agent 行为的规则变更按风险补前向试用）。

## 证据能证明什么

如实记录检查命令/方法、工作目录、输入来源与执行/跳过统计（仅用户明确要求独立交付验证报告时才选用 [验证模板](../templates/verification.md)）：

- 零测试执行、目标用例被跳过或仅编译通过，不能证明目标行为已验证。
- 局部 Mock 只证明隔离逻辑，不证明真实数据库、鉴权链或事务回滚已打通。
- 报告文件存在、工具返回 `success`、子 Agent 声明 `done` 或已有 commit，均不替代实际内容与验收覆盖核对。
- 检查失败、环境缺失、未执行与未知分开表述；未知既不写成失败，也不写成通过。

## 复用与失效

- **有效即复用**：目标、目录、代码、配置与测试输入均未变化时直接复用已有检查结果，不因切换阶段或执行者机械重跑。
- **按影响补验**：代码、依赖、配置、共享资源或分支整合发生变化时，仅对受影响范围与整合新增风险补跑检查；最终整合核验期间暂停相关写入。

## 缺口与发现分流

只有目标实现、当前有效证据充分、已约定的必要扩展检查关闭且无实质阻塞时，才确认整项验收完成；仅完成本地部分或存在环境缺口时直接点明待办，不为收尾将必要检查降为可选。核验或审查发现先按以下四类分流，不将审查标签直接当作扩范围授权：

| 发现 | 处理 |
| --- | --- |
| 本次引入的缺陷 | 已有实施授权内修复；纯核验请求仍不自动授权修改 |
| 会直接破坏本次验收的存量问题 | 说明具体调用关系与失败场景，选择最小修复；涉及扩范围、改契约或外部影响时先确认，未解决前受影响验收不标通过 |
| 无直接关系的历史问题或可选改善 | 披露影响与建议，不自动转成当前任务或阻塞；严重隐患明确提醒但不擅自改代码 |
| 环境、部署或证据缺口 | 保留具体缺口、负责方与安全下一步，不自建模拟设施冒充真实环境已验证 |
