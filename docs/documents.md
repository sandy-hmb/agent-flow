# 文档与记录

首次生成或实质修改正式文档时读取；同会话按变化补读，不要求每次回复落盘。

## 是否需要文档

简单修复、短调查或核验可直接回复。需要跨会话继续、独立读者、正式审阅或可复用长正文时才持久记录。先找目标项目已有文件并原地更新；没有适用位置才新建，不默认生成全套文档或迁入 `.workspace`。

模板先满足用户明确的有效要求与项目已有约定；已选扩展的专业输出用其模板；其余通用文档按 [模板索引](../templates/README.md) 只选当前一种。未列出的文档可按本规范组织。确定需要落盘后再读取适用模板，模板不构成操作授权。

## 内容质量

文档让读者无需还原聊天即可做下一步：知道要解决什么、哪些依据可信、已经决定什么、仍需谁决定什么，以及如何执行或核对。调查帮助判断结论是否成立，需求让验收可观察，设计让实施者理解行为与边界，计划让交付和检查可执行，验证说明让读者分清已证实结果与缺口；具体内容槽位由对应模板维护，不在此复制清单。

内容的具体程度跟随猜错的代价：兼容、数据、安全或跨任务契约等高风险点写清规则，授权内低风险细节保留实施空间。完整例子见 [按需写作示例](examples/document-quality/README.md)，仅在需要对应写法时阅读；例子不是新增默认产物或授权。

## 内容归属

| 内容 | 唯一维护位置 |
| --- | --- |
| 普通任务的范围、验收、必要方案和当前进展 | 现有任务记录；需要新记录时可用 `work.md` |
| 已独立拆出的需求、方案、任务定义或调查正文 | 相应正式文档；工作记录只留入口、当前结论及必要变更影响 |
| 执行安排 | 无独立计划时在工作记录，有独立计划时在计划中；另一处只引用 |
| 任务执行进展、未关闭项与下一步 | 工作记录顶部的当前概览；按已有任务标识引用，不在计划里再建一套可变状态表 |
| 完整人工验证说明 | 工作记录或独立验证文档择一；另一处只留当前结论和链接 |
| 工具日志、机器报告、外部回执 | 原来源；人工记录解释覆盖和限制，不复制全量日志 |

文件位置、维护者和允许输出范围沿用当前项目/任务约定；需要协作时先明确归属。协调者维护主记录，子任务返回事实，由协调者核对后更新。扩展不得覆盖已批准主规格；实质变化返回协调者处理。

设计说明技术规则、流程和取舍；计划说明每项任务的允许范围、交付结果、直接依赖、规格引用及验证责任。已有规格时按章节或验收标识引用，不在计划重述算法、字段定义或整套测试矩阵；未独立维护的必要细节仍写在当前权威位置，不能只留无内容的引用。

## 当前概览与历史

- 工作记录顶部简述当前结论、关键产物或入口、未关闭项及影响、负责方和安全下一步。按本项需要组织，不强制状态枚举或表格；已有记录无需仅为套用结构而重排。
- 更新时修正或移走已过时的当前描述，不向“当前进展”无限追加操作过程。历史基线、当时未提交状态与当前版本明确区分，读者不应靠还原时间线才能知道现场。
- 仅在影响范围、决策或恢复时保留带日期的关键里程碑，说明决定及影响、引用原依据，不再建一套当前状态。概览只摘要验证结论并引用详细证据，不复制完整验证说明；不要在文末再维护同一份下一步。

## 写入与更新

- 正文明确用途、范围、真实来源；只有确有时效性时写适用版本或日期，未知就写未知及影响，不编造基线、审批人或实际检查。
- 分开表达事实、推断、待决定、已批准与实际执行。计划中的动作不是已经发生，模板里的结构不是证据。
- 同一文件原地维护，不默认建立 `final`、`v2`、日期版或阶段摘要。实质变更说明对范围、决策、验收的影响，必要时重新核对授权；编辑性调整不机械重复批准。重要历史沿用项目版本控制或记录方式保留。
- 每段或条目围绕一个结论，长过程按实际关系拆分或引用。命令、哈希和工具细节只保留支持判断或恢复所需的部分，不把完整操作轨迹粘进正文，不设机械字数或行数门槛。执行安排保留实际目录、角色、写入边界与必要恢复标识，不默认罗列已结束 Agent 的宿主配置。
- 写作后删除模板使用说明、占位和不适用章节；条件章节可删，影响执行的风险、未知和待决定项不可为求完整而隐去。表格只用于真实的结构化关系。
- 不写凭据和不必要的个人数据。链接从文件实际位置解析并核对目标；临时目录、仅本机可见路径或可能过期的报告明确持久性限制，需要长期接手时按项目允许方式保留。

## 接手与自审

暂停、取消、等待或失败时，在现有记录中说明当前事实、未完成改动、必要来源、活动写入者和安全下一步。新会话先核对实际目录、产出和依据变化，历史通过不自动等于当前有效。

落盘后轻量自审：能否直接看出当前状态和下一步，历史描述是否与当前事实混淆，目标是否覆盖，内容与权威文件是否一致，来源和链接是否有效，是否有未知伪装成事实、残留占位、同义重复或双写。自审不另生成报告；证据如何支持完成见 [验证规范](verification.md)。

## 维护规则与示例

按实际失败类型选择表达：越权风险用明确边界与必要反例，产物形态用正向配方，易漏信息放在对应模板槽位，条件规则写可观察的触发条件；可机械验证的结构用已有检查维护，不用关键词测试代替语义判断。示例只补难以从规则理解的写法，按需链接并标明教学性质，同一要求仍只有一个权威位置。
