# 文档与记录

首次生成或实质修改正式文档时读取；同会话按变化补读，不要求每次回复落盘。

## 是否需要文档

简单修复、短调查或核验可直接回复。需要跨会话继续、独立读者、正式审阅或可复用长正文时才持久记录。先找目标项目已有文件并原地更新；没有适用位置才新建，不默认生成全套文档或迁入 `.workspace`。

模板先满足用户明确的有效要求与项目已有约定；已选扩展的专业输出用其模板；其余通用文档按 [模板索引](../templates/README.md) 只选当前一种。未列出的文档可按本规范组织。确定需要落盘后再读取适用模板，模板不构成操作授权。

## 内容归属

| 内容 | 唯一维护位置 |
| --- | --- |
| 普通任务的范围、验收、必要方案和当前进展 | 现有任务记录；需要新记录时可用 `work.md` |
| 已独立拆出的需求、方案、任务定义或调查正文 | 相应正式文档；工作记录只留入口、当前结论及必要变更影响 |
| 执行安排 | 无独立计划时在工作记录，有独立计划时在计划中；另一处只引用 |
| 任务执行进展 | 默认在工作记录，不在计划里再建一套可变状态表 |
| 完整人工验证说明 | 工作记录或独立验证文档择一；另一处只留当前结论和链接 |
| 工具日志、机器报告、外部回执 | 原来源；人工记录解释覆盖和限制，不复制全量日志 |

文件位置、维护者和允许输出范围沿用当前项目/任务约定；需要协作时先明确归属。协调者维护主记录，子任务返回事实，由协调者核对后更新。扩展不得覆盖已批准主规格；实质变化返回协调者处理。

## 写入与更新

- 正文明确用途、范围、真实来源；只有确有时效性时写适用版本或日期，未知就写未知及影响，不编造基线、审批人或实际检查。
- 分开表达事实、推断、待决定、已批准与实际执行。计划中的动作不是已经发生，模板里的结构不是证据。
- 同一文件原地维护，不默认建立 `final`、`v2`、日期版或阶段摘要。实质变更说明对范围、决策、验收的影响，必要时重新核对授权；编辑性调整不机械重复批准。重要历史沿用项目版本控制或记录方式保留。
- 写作后删除模板使用说明、占位和不适用章节；条件章节可删，影响执行的风险、未知和待决定项不可为求完整而隐去。表格只用于真实的结构化关系。
- 不写凭据和不必要的个人数据。链接从文件实际位置解析并核对目标；临时目录、仅本机可见路径或可能过期的报告明确持久性限制，需要长期接手时按项目允许方式保留。

## 接手与自审

暂停、取消、等待或失败时，在现有记录中说明当前事实、未完成改动、必要来源、活动写入者和安全下一步。新会话先核对实际目录、产出和依据变化，历史通过不自动等于当前有效。

落盘后轻量自审：目标是否覆盖，内容与权威文件是否一致，来源和链接是否有效，是否有未知伪装成事实、残留占位、同义重复或双写。自审不另生成报告；证据如何支持完成见 [验证规范](verification.md)。
